# codex-pool 演进路线图

> 现状: 本地号池 + GUI 手动切换(选中 → use)。本路线图只做规划, 不承诺时间。

## 阶段一(P0): 本地自动切换 —— 5h/周额度打满自动换号

> **状态: 已实现 (v0.2.0)**。默认影子模式(只告警), 在 auto 设置中开启执行模式。
> 选号策略 least_used(周额度优先), 检查间隔 30/10/5 分钟分层, 每小时切换上限,
> 触发阈值可调(默认 100=真打满才切, 可调低至 80 做预测性切换), 切换后可自动重启
> Codex Desktop(MSIX AppID 动态查找)。

**目标**: 当前账号 `limit_reached`(打满, Codex 已不可用)时, 自动切换到
最优槽位。**只在打满时切**——打满意味着 Codex 本来就拒绝请求, 不存在
"打断进行中任务"的问题; 未打满绝不自动切。

**实现位置**:
- `codex-pool.py`: 新增 `pick_best_slot()`(选周额度最低且未打满的槽位)
  与 `cmd_watch()`(CLI 子命令 `watch`, 供无 GUI 场景)
- `codex-pool-gui.py`: 操作台加 "auto 自动切换" 开关; 后台 watcher 线程
  (每 5-10 分钟查询当前号用量, 复用现有 `fetch_usage` / `kill_codex` /
  切换流程, 全套锁与防护原样生效)
- 配置: `pool.json` 增加 `auto_switch` 节(enabled / interval_min / max_per_hour)

**前置条件**: 先在下一次手动切换中实战验证 v0.1.1 的 ChatGPT.exe 宿主
退出修复——自动切换完全依赖它。

**可选增强**:
- 切换后自动重启 Codex Desktop(MSIX 可用 `shell:AppsFolder` 拉起, 稳定性待验证)
- 全员打满时弹 Windows 通知 + 显示最早重置时间(重置时间数据已有)

**可行性: 高**。所有部件(额度查询/打满判定/安全切换/锁与冷却)已存在,
新增代码约 200 行, 主要工作量在策略细节与实测。

**优缺点**:
- ✅ 切换零感知(在本来就被卡的瞬间完成)、池子利用率拉满、无人值守
- ✅ watcher 本身就是未来 API 网关的账号管理内核, 不白做
- ⚠️ 自动化切换频率上升, 风控可见性略增(缓解: 只在打满时切 + 每小时上限)
- ⚠️ GUI 需保持开启(阶段 1.5 用计划任务跑 headless 解决)

## 阶段 1.5: 无 GUI 常驻

`codex-pool watch` 交给 Windows 计划任务/启动项, 不开 GUI 也能自动切换。
可行性: 高, 纯工程问题。

## 阶段二: VPS 远程监控(只读) —— 腾讯云 VPS 的用武之地

> **状态: 已实现 (v0.3.0)**。`codex-pool-monitor.py` 单文件部署(stdlib 零依赖):
> GUI 侧配置 vps 地址后, 切换/收号/查额度时自动推送快照(仅 access_token,
> 不含 refresh_token); 服务端自轮询额度(绝不刷新 token), 状态页 + JSON API,
> 401/打满/全员打满事件推送(Telegram/Webhook)。见 README 部署一节。

VPS 跑一个只读小服务: 定时查询全部槽位额度 → 产出状态页/推送通知
(Telegram/Bark)。**VPS 不执行切换**——auth.json 在本地, 切换必须在本地。

腾讯云 VPS 可用性判定:
- 国内节点: 无法直连 chatgpt.com/auth.openai.com, 需自备出口, 不推荐
- 香港/海外节点(轻量应用服务器等): 可直连, 可用

注意: VPS IP 会成为第二个触碰全部 token 的出口(IP 关联信号 +1),
若介意可让 VPS 的查询也走家宅出口。

可行性: 中高, 一天工作量; 价值在于人不在电脑前时的额度/封号告警。

## 阶段三: API 收束(中转网关) —— 触发条件出现后再做

one-api/new-api 系网关或自研 codex 协议翻译层, 把号池变成一个
OpenAI 兼容端点。**仅当出现"多设备/多工具/多人共享"需求时启动**,
否则本地池更优。

前置风险必须接受:
- 机房 IP 集中承载全部账号, 单点热度高(账号寿命预计短于本地池)
- 非公开后端接口漂移需持续追改(已经历 rate_limits→usage 一次)
- 多账号自动化转发是风控重点画像, 与"自用"与否无关

可行性: 中(组件成熟但胶水层需持续维护)。

## 风险与纪律(全阶段通用)

1. 所有自动化的前提: 单次切换的全部防护(锁/备份/校验/冷却)不可绕过
2. 自动化失败必须显式告警, 不允许静默降级成"看起来在自动切换"
3. 每阶段先跑一周影子模式(只告警不切换)再放开执行
